# 한글·한자 변환 데이터베이스 1-Pager

## Background

HOP에는 선택 영역을 읽고 바꾸는 편집 경로와 단축키 재정의 지점이 있다. F9 변환에서는 먼저 선택한 한글 단어와 일치하는 한자어 후보를 보여 주고, 단어 후보가 없으면 각 한글 음절에 대응하는 한자와 훈음(뜻+음)을 보여 줄 데이터가 필요하다.

## Problem

국립국어원 사전 API만으로는 오프라인에서 즉시 사용할 대규모 단어 후보와 글자별 훈음을 함께 제공하기 어렵다. API 키, 호출 제한, 네트워크 지연이 있고 표준국어대사전의 한자어 원어 필드는 글자별 훈을 제공하지 않는다. 여러 데이터의 라이선스도 서로 달라 하나의 불명확한 산출물로 합치면 재배포 조건을 추적하기 어렵다.

## Goal

- 고정된 원천 버전과 SHA-256으로 다시 만들 수 있는 UTF-8 JSON 데이터베이스를 제공한다.
- 단어 전체 변환 후보와 글자별 음·훈 후보를 모두 지원한다.
- 최초 실행부터 네트워크나 API 키 없이 조회할 수 있게 정적 자산으로 배포한다.
- 출처와 라이선스를 파일 단위로 명확히 표시한다.
- F9에서 선택 영역 또는 현재 한글 단어를 찾아 단어 후보를 먼저 보여 주고, 없으면 음절별 후보를 제공한다.
- 적용한 변환을 편집기의 단일 undo 단위로 기록한다.

## Non-goals

- 단어 후보의 언어 모델 기반 문맥 순위화나 사용자 학습을 구현하지 않는다.
- 표준국어대사전 Open API를 빌드 또는 실행 시 필수 의존성으로 만들지 않는다.
- `third_party/rhwp`를 수정하지 않는다.
- 여러 문단에 걸친 선택, 머리말·꼬리말·각주 내부의 변환은 첫 구현 범위에 포함하지 않는다.

## Constraints

- 새 패키지 의존성을 추가하지 않고 Node.js 24 내장 API만 사용한다.
- 빌드 결과는 macOS, Windows, Linux에서 동일해야 한다.
- 대용량 단어 데이터는 첫 음절의 초성별로 나눠 필요한 파일만 읽을 수 있게 한다.
- 한국어기초사전 데이터가 들어간 단어 산출물은 CC BY-SA 2.0 KR 조건으로 별도 취급한다.
- 글자 산출물에는 libhangul `hanja.txt`의 BSD-3-Clause 고지와 Unicode License v3 고지를 유지한다.

## Sources and schema

### 글자 DB

- libhangul `hanja.txt`: 한글 음절→한자와 한국어 훈음. 커밋과 원문 SHA-256을 고정한다.
- Unicode Unihan 17.0.0: `kHangul`, `kDefinition`, `kKoreanEducationHanja`, `kKoreanName`, `kTotalStrokes`를 보강한다.
- `characters.json`은 한자를 키로 하고 `readings`, `labels`, `meanings`, 교육용/인명용 여부, 영문 정의, 총획수를 저장한다.
- `readings.json`은 한글 음절을 키로 하여 한국어 훈음이 있는 한자만 바로 찾게 한다. 교육용 한자, 훈음 수, 인명용 한자, 코드 포인트 순으로 후보를 정렬한다.

### 단어 DB

- libhangul `hanja.txt`: 한글 표제어→한자 후보의 기본 목록과 원래 순서를 보존한다.
- 한국어기초사전 2026-07-19 전체 JSON: 일치하는 원어, 정의, 품사, 어휘 등급을 보강한다.
- 표준국어대사전 2026-06-05 전체 XML: `단어`이면서 표제어와 한자 원어의 글자 수가 일치하는 163,626쌍을 보강한다. 공식 전체 내려받기는 로그인이 필요하므로 재현 가능한 공개 미러의 고정 커밋에서 추출한 보강 파일을 저장한다. 뜻풀이와 용례는 포함하지 않는다.
- 각 후보의 `source`는 비트 마스크다. `1`은 libhangul, `2`는 한국어기초사전, `4`는 표준국어대사전이며 합산 값은 여러 원천에서 확인된 후보이다.
- `words-<초성>.json`은 `entries` 객체 안에 한글 표제어별 후보 배열을 저장한다. 초성 파일명은 `g`, `gg`, `n`, `d`, `dd`, `r`, `m`, `b`, `bb`, `s`, `ss`, `ng`, `j`, `jj`, `ch`, `k`, `t`, `p`, `h`, `other`이다.

`manifest.json`은 스키마 버전, 원천 URL·버전·SHA-256, 라이선스, 한국어 훈음 보유 범위, 파일별 SHA-256·바이트 수·항목 수를 기록한다. 자세한 재배포 고지는 같은 디렉터리의 `THIRD_PARTY_NOTICES.md`에 둔다.

## Implementation outline

- `scripts/build-hanja-database.mjs`가 원격 원천 세 개와 로컬 표준국어대사전 보강 파일의 체크섬을 검증한다.
- `scripts/extract-stdict-hanja-supplement.mjs`는 표준국어대사전 XML 디렉터리에서 안전한 한글↔한자 쌍만 추출한다. 현재 보강 파일은 `spellcheck-ko/korean-dict-nikl`의 커밋 `42c0d01889f34536e9cf94fe57f62bd2055b1bde`로 재현한다.
- 최소 ZIP 판독기는 저장 및 DEFLATE 항목만 처리하며 예상하지 않은 형식은 즉시 실패한다.
- 파서는 NFC 정규화, 중복 병합, 안정적인 키 정렬을 수행한다.
- 한국어기초사전 원어는 한글 표제어와 글자 수가 같고 한자를 포함하는 안전한 변환 후보만 추가한다.
- 표준국어대사전은 구·속담·띄어쓰기 표제어를 제외하고, 한글 또는 한글+한자로만 일대일 대응되는 단어만 추가한다.
- 생성 결과는 `apps/studio-host/public/dictionaries/hanja`에 둔다.
- Studio 런타임은 매니페스트와 글자 색인을 지연 로드하고, 단어의 첫 음절에 해당하는 초성 샤드만 읽어 캐시한다.
- `edit:convert-hanja` 명령이 선택 영역을 우선 사용하고, 선택이 없으면 현재 커서가 속한 연속 한글 범위를 계산한다.
- 단어 후보 창은 완성된 한자어와 글자별 훈음을 표시한다. 정확한 단어 후보가 없을 때는 음절별 후보와 조합 미리보기를 표시한다.
- 본문, 표 셀, 중첩 셀의 같은 문단 치환은 upstream 편집 명령 라우터를 통해 한 번의 undo 단위로 적용한다.
- 데이터 로드 또는 후보 선택 중 편집 범위가 바뀌면 치환을 취소한다.

## Verification plan

- `pnpm run dictionary:build`
- `pnpm run dictionary:verify`
- `pnpm run test:dictionary`
- 대표 글자 `學`, `樂`, `歷`의 음·훈과 대표 단어 `학교`, `사기`의 복수 후보를 확인한다.
- 표준국어대사전 보강 대표값 `가감되다→加減되다`, `가공물→加工物`, `가건축→假建築`을 확인한다.
- 매니페스트와 모든 파일의 해시·개수·샤드 배치를 다시 계산한다.
- 생성기를 두 번 실행해 동일한 파일 해시가 나오는지 확인한다.
- F9 단축키와 명령 등록, 샤드 지연 로드·캐시, 단어 우선/fallback 조회, 현재 단어 판별, stale 범위 거부를 Vitest로 확인한다.
- 후보 창의 Enter/Escape/방향키 동작과 음·훈 렌더링을 확인한다.
- `pnpm run test:studio`와 `pnpm run build:studio`를 실행한다.

## Rollback or recovery notes

데이터 크기나 라이선스가 배포에 부적합하다고 판단되면 `edit:convert-hanja` 명령과 `apps/studio-host/public/dictionaries/hanja`, 관련 UI·스크립트를 함께 제거한다. 변환은 독립된 HOP command contribution이므로 기존 upstream 편집 명령이나 문서 형식에는 영향을 주지 않고 되돌릴 수 있다.
