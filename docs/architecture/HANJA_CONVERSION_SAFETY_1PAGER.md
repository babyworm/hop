# 한글·한자 변환 안전성 보강 1-Pager

## Background

HOP의 F9 한자 변환은 선택 영역 또는 현재 한글 단어를 오프라인 사전에서 조회하고, upstream 편집기 명령 라우터를 통해 한 번의 undo 단위로 치환한다. 최초 구현 리뷰에서 문자열 치환 경로와 문서 수명주기, 대화상자 키보드 처리, 정적 사전 신뢰 경계에 안전성 공백이 확인됐다.

## Problem

- 삭제 뒤 삽입하는 복합 명령은 삽입 실패 시 원문을 잃을 수 있고, 성공해도 기존 문자 서식을 대체문에 재적용하지 않는다.
- 문서 generation이 실제 WASM 문서 교체보다 늦게 바뀌어 이전 문서에서 연 대화상자가 새 문서를 수정할 수 있다.
- upstream 키 처리기가 객체·셀 선택을 해제한 뒤 F9를 dispatch하므로 금지된 선택 모드를 우회할 수 있다.
- 대화상자의 Enter와 Tab 처리, 후보 클릭 뒤 포커스가 일관되지 않다.
- 런타임이 JSON 스키마 외의 후보 무결성을 충분히 검증하지 않고, generated JSON의 byte hash는 CRLF checkout에서 달라질 수 있다.

## Goal

- 본문과 평면 표 셀에서 한자 치환이 원자적으로 실패하고 혼합 문자 서식을 보존하며, undo/redo도 같은 서식을 복원하게 한다.
- 실제 문서 mutation 경계에서 generation을 갱신하고, F9를 upstream보다 먼저 안전하게 판정한다.
- 모달의 Enter, Tab, listbox 포커스 계약을 키보드와 포인터 모두에서 일관되게 만든다.
- 잘못된 사전 데이터가 대체 문자열로 노출되기 전에 asset 단위 오류로 거부되게 한다.
- Windows를 포함한 모든 checkout과 build에서 동일한 generated bytes를 검증한다.

## Non-goals

- `third_party/rhwp`를 수정하거나 새 편집기 API를 추가하지 않는다.
- 사전 순위화, 사용자 학습, 네트워크 조회를 추가하지 않는다.
- pinned upstream이 경로 기반 문자 서식 API를 제공하지 않는 중첩 표 셀 변환을 모의 지원하지 않는다.
- 새 패키지 의존성을 추가하지 않는다.

## Constraints

- `pnpm`과 기존 TypeScript/Rust 경계만 사용한다.
- macOS, Windows, Linux에서 동일하게 동작해야 한다.
- 한 번의 변환은 history에서 한 명령이어야 하며 upstream의 유한 snapshot 저장소를 사용하거나 축출하지 않아야 한다.
- 실패 복구는 캡처한 원문·문자 서식 run과 가역 텍스트 연산만 사용한다.
- Hanja asset 내용이나 문서 본문을 로그에 남기지 않는다.

## Implementation outline

1. HOP 전용 치환 명령이 원문 문자 서식 run을 캡처하고 삭제·삽입·서식 적용을 가역 transition으로 수행한다. 최초 실행이 실패하면 원문과 서식을 복원해 오류를 반환하고, undo/redo의 일시 오류는 원상 복구 뒤 한 번 재시도한다. 공유 snapshot 저장소는 건드리지 않는다.
2. 본문에는 `getCharPropertiesAt`/`setCharShapeId`, 평면 표 셀에는 대응 cell API를 사용한다. 중첩 셀은 변환 source 단계에서 명시적으로 거부한다.
3. 주 문서용 `WasmBridge` 하위 클래스가 `loadDocument`와 `createNewDocument` 직전에 generation을 갱신하며 Web과 Tauri가 같은 seam을 사용한다.
4. document capture 단계의 순수 F9 handler가 modifier 없는 F9를 선점해 dispatcher에 전달한다. 기존 shortcut matcher의 F9 항목은 제거한다.
5. 모달은 listbox만 후보 탐색 tab stop으로 유지하고, Enter는 실제 후보 list에 포커스가 있을 때만 적용하며, 경계 Tab을 모달 안에서 순환시킨다.
6. 정적 사전 parser를 별도 모듈로 분리해 manifest, 글자, 읽기 색인, 단어 후보를 깊게 검증한다.
7. generated JSON을 LF로 고정하고 `dictionary:verify`를 dictionary build와 Studio build의 선행 gate로 연결한다.

## Verification plan

- 회귀 테스트를 먼저 추가하고 각 결함이 기존 구현에서 실패하는지 확인한다.
- 실제 bundled WASM에서 서로 다른 두 문자 서식을 가진 `학교`를 `學校`로 바꾼 뒤 convert/undo/redo의 텍스트와 `charShapeId`를 확인한다.
- 삽입 및 서식 적용 실패를 주입해 원문·서식·history가 보존되는지 확인한다.
- Web/Tauri 문서 load/create 중 이전 source가 즉시 stale이 되는지 확인한다.
- F9 선택 모드, 모달 Enter/Tab/포커스, malformed dictionary, LF attribute를 집중 테스트한다.
- `pnpm run test:studio`, `pnpm test`, `pnpm run dictionary:verify`, `pnpm run build:studio`, TypeScript 진단과 `git diff --check`를 실행한다.
- 브라우저에서 실제 WASM 문서를 열어 F9 변환, 취소, 적용, undo/redo, 키보드 포커스를 수동 확인한다.

## Rollback or recovery notes

모든 변경은 `apps/studio-host`, root build script, generated-file attributes와 문서에만 한정한다. 문제가 생기면 새 HOP bridge/command/parser와 연결 지점을 되돌리면 기존 데이터 산출물과 upstream submodule은 영향을 받지 않는다. 중첩 셀 차단은 path-aware 문자 서식 API가 upstream에 추가된 뒤 별도 테스트와 함께 해제한다.
